# 空格子说出自己是哪一种空

`validate.py` 第 5 道检查的说明。

## 起因

四道闸全绿的那一周被连着问出三个问题，**三个都不是数值错，全在呈现层**：

- **一、单位。** 族系旗舰表以「元素/token」为主键、DeepSeek 精度表以「字节/token」为主键，
  两张表并排，列名离数字十几个字符。`DeepSeek-V4.1-Flash` 的 `1,600`（元素）被读成字节，
  与另一张表的 `890 B` 对不上，看起来像数据错了。两个数都对：
  1,600 元素 = 全局 KV 1,280 + indexer 320，890 / 1600 = 0.556 B/元素。
- **二、`—` 一个符号背着三种含义**：没查 / 不适用 / 查了但没有。45 份记录的
  `precision.kv_cache` 是空的，真相是「厂商没公布，字节按权重 dtype 兜底」——
  **那是一条结论，不是缺口**，可它和「还没查」渲染成同一个符号。
- **三、取数口径。** 精度表只显示本仓取数那个仓，厂商的多精度独立发布不可见。
  MiniMax-M3 确实是 BF16，厂商另发的 MXFP8 变体本仓未录，于是表上看着像
  M2 都低精度了而 M3 莫名倒退。

共性：**数字没错，而读者无从判断一个格子里的数是什么量、或者一个空格子是什么意思。**

## 做法：把区分推进数据层

最省力的修法是在模板里把 `—` 换成一句话。那只是把问题挪了个地方，下一张新表会重犯。
区分放在 [`data/schema/columns.json`](../data/schema/columns.json)，
由 [`scripts/lib/columns.py`](../scripts/lib/columns.py) 读取。

### 缺值的三态

| 态 | 含义 | 是缺口吗 |
|---|---|---|
| `unsurveyed` | 本仓还没查、或查了还没录进记录。这是调研进度，不是模型事实 | 是 |
| `not_applicable` | 这一代结构上没有这个东西，不存在可填的值 | 不是 |
| `confirmed_absent` | 查过，确认厂商没公布 / 这一代不做这件事。**这是信息** | 不是 |

判定写在每一列的 `absent` 上：一个默认态，加若干条按顺序试的规则（第一条命中的赢）。
规则的 `test` 用一个固定的小词表（`truthy` / `absent` / `eq` / `in` / `not_in` / `matches`）。
判不出来一律落到 `unsurveyed` —— **不替记录把话说满**：默认报「不适用」会把调研缺口
渲染成模型事实，那正是要修的那个错。

两条设计上要说清的：

- **「不适用」和「查了但没有」是在替记录下结论，所以必须给 `why`**（闸口强制）。
  「未录」是进度陈述，三态表里的通用说明就够了。
- **一个按列写死的默认态只能有「对每一份记录都成立」那么强。** 所以结构性的列不写死，
  而是挂一条结构判据：`kv_lora` 的空格子在非 latent 注意力上是「不适用」，
  在 MLA / hybrid 上是「未录」（26 份有这个结构，只有 16 份填了）。

### 闸口查什么

`validate.py` 的第 5 道，只查**声明**不查渲染：

- 每一列都有 `absent` 声明；态必须是三态之一
- `not_applicable` / `confirmed_absent` 必须有 `why`
- 规则的 `op` 必须实现了、`test` 必须有 `path`
- 声明了 `quantity`（一种会被读错成别的量的物理量）的列必须有 `unit`
- `scope: measured` 的列必须有 `scope_from`（说得出测自哪个仓）
- 逐记录把每个空格子判一遍，判不出来就报错；判成「未录」的攒成一份清单
  （`--list-gaps`）—— 那是调研进度，该有人看见还剩哪些没查

**渲染侧不在这道闸里。** 站点怎么画这三态有它自己的归属；在这里顺带查会变成两道闸
管同一件事，而两道闸迟早会各自漂 —— `bytes_basis` 的标签表就是这么变成三份各自不全的
拷贝的（`kv_table.py` 的 `BASIS_DOC`、`data.ts` 的 `KV_BASIS_LABEL`、
`models/[id].astro` 的 `KV_BASIS`，`vendor_declared` 进了 `derive.py` 和 schema 之后，
三个用它的地方一个都没跟上）。同理，`bytes_basis` 的取值表与标签**不在 `columns.json` 里**。

## 回归用例

`tests/absence_regression.py`，19 条，三次误读各有负例与正例：

```
.venv/bin/python tests/absence_regression.py -v
```

**负例**把那次误读的条件重新造出来，断言闸口报错（去掉 `unit`、去掉 `absent` 声明、
判「不适用」却不说凭什么、用没实现的 `op`、态写成三态之外的值、实测列不说测自哪里）。
**正例**拿真实的 47 份记录断言结论：45 份空着的 KV 精度判成「查了但没有」而不是「未录」、
三态都真的用得上没有一态是摆设、结构判据分得开「不适用」与「未录」、
声明了而实测清单里没有的正好是那三份通义、四份「逻辑精度 vs 容器」不被误报。

把 `check_absence_contract` 掏空重跑，6 条负例全部失败 —— 用例不是摆设，验过。

## `weights_release` 的口径（已迁完）

同一种情况两种相反的记法同时存在：

- **通义**列厂商发布过的**全部变体**，含从没取数的独立仓：`qwen3.5-27b` /
  `qwen3.5-397b-a17b` 声明 `[BF16, FP8_E4M3, INT4]`，`qwen3.8-2.4t-a95b` 声明
  `[BF16, FP8_E4M3]`，而完整权重清单里那些低精度一个都没有
- **MiniMax-M3** 只列本仓取数那个仓实测到的（`[BF16, FP32]`），厂商另发的 MXFP8
  只写在 `benefit` 的散文里

两种都讲得通，同时存在不行：读者无从知道一行「BF16」是「厂商只发过 BF16」还是
「本仓只取了 BF16 那个仓」，而精度表只显示取数那个仓。

**约定是「列厂商发布过的全部变体 + 每一项标记取没取过数」。**
`precision.weights_release_scope`，每种精度一条 `{measured, repo?, container?, note?}`。
`measured: false` 就是「厂商发过、本仓没取数」那一半，它让不可见的东西可见。

**40 份带 `weights_release` 的记录已经全部迁完**（另有 7 份 DeepSeek 没有这个字段，
不涉及）。`measured` 从 `derived` 的 `from_shapes.weight_bytes_by_dtype` 算 —— 那是全量
清单的 dtype 直方图，粒度和 `weights_release` 对得上。仓名只从各记录自己已有证据的散文里
取（HF 名单），不构造。带仓名的三份标 `judgement` 进 Gate C：断言「那个仓存在且装的是
这种精度」是判断；其余标 `derived`，只是把清单里有没有这种 dtype 照实记下来。

这和上面的三态是**同一个语义家族**，不另起一套词汇：`measured: false` 对应
「查了但没有（在这个仓里）」，不是「没查」。

### 和 `e4983d4` 那道闸的接缝

`check_release_vs_measured` 认这个字段：某个变体标了 `measured: false`（在独立仓）
或带了 `container`（逻辑精度装在别的容器里），就算交代过，放行；没交代的报。

**迁完之后这一条已经从 warning 收紧成 error** —— 没交代又对不上，现在没有任何正当理由。
新录一份记录时，`weights_release` 里写了本仓清单查不到的精度，就必须同时说清它在哪个仓。

放行只认 `measured: false` 和 `container` 两种。**`measured: true` 不算交代** ——
声明了、实测清单里查无实据、却标「取过数」，那是自相矛盾，继续报。回归用例钉住了这条。

### 排雷：7 份声明与实测不符，其中 4 份不要改

| 记录 | 声明 | 清单里 | |
|---|---|---|---|
| `deepseek-v41-flash` | FP4 | I8 | FP4 装 INT8 容器 |
| `kimi-k2-thinking` / `kimi-k2.5` | INT4 | INT32 | pack-quantized，8 个 INT4 一个 I32 |
| `kimi-k3` | MXFP4 | UINT8 | MXFP4 一字节两个 |

这四份是「逻辑精度 vs 容器」的**正确记法**，用 `container` 字段表达，不要改声明。
真正「另发了仓、本仓没取数」的只有那三份通义。

**这四份现在不会被误报，而且不是靠白名单**：`derive.py` 在 `packing_factor > 1` 时
已经把容器换成逻辑精度，所以 `weight_bytes_by_dtype` 里本来就是 `FP4` / `INT4` / `MXFP4`。
判据挂在 `packing_factor` 上是有意的 —— 写死白名单的话，下次出现新打包格式会漏。
回归用例里有一条专门钉住这件事。

**不要拿 `per_subsystem` 去比**：那是每个子系统的**代表** dtype，粒度比 `weights_release` 粗。
glm 一代声明 `[BF16, FP32]`，FP32 只有 57,600 B（路由 gate 那一类），
`per_subsystem` 每个桶都是 BF16 —— 照它比会把「同一个仓里的少数张量」误报成
「厂商另发了一个仓」，13 份里 10 份是假的。拿两个粒度不同的量相比，本身就是范畴错误。

## 边界与待办

- **判「已穷举过清单」现在靠 `subsystem_method` 的散文正则**（`columns.json` 里唯一一处
  靠文本判断的规则）。当前判得对 —— 42 份判「已穷举」，`ds-v3.1` / `minimax-m3` /
  `step-5-preview` 三份判「未录」，和它们自述的抽样口径一致 —— 但这是散文正则，
  迟早会错。应改成 `subsystem_method.exhaustive` 布尔字段，届时规则换成 `op: truthy`。
- **`--list-gaps` 现在只攒逐子系统那一类。** 其余列的「未录」没有攒，因为大部分列
  本来就填着值；要扩就把攒的范围放开。
- **`--list-gaps` 现在是 3 份**（`ds-v3.1` / `minimax-m3` / `step-5-preview`），
  都是真的按抽样取的数，不是漏录。两份通义的 `per_subsystem` 已由别的线补上。
- **`weights_release` 里缺的变体没有补。** 口径说「列全部变体」，而 MiniMax-M3 的
  `MXFP8` 变体（记录散文里提到、本仓未录）**没有加进 `weights_release`** ——
  加一个变体要有来源，而散文里只说存在、没有仓名与日期。这是口径统一剩下的最后一块：
  要补的是 M3 这一份，补法是先给 MXFP8 找到可定位的来源，再进 `weights_release`
  并配 `measured: false`。闸口管不到这一类（它只能查「声明了而清单里没有」，
  查不出「厂商发了而记录没声明」）。
